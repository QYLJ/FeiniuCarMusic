# HLS audio demux fixtures

These are local, synthetic, one-second stereo 440 Hz sine waves, generated by
FFmpeg 8.1.2 at 44,100 Hz. No NAS credentials, music recordings or network traffic
are included. Each codec has an actual FFmpeg fMP4 HLS initialization file and five
segments; the final FLAC segment is the empty `styp` trailer FFmpeg emits.

Generation command (run once per codec, with `CODEC` replaced by `flac`, `mp3` or
`aac`; codec options are listed below):

```text
ffmpeg -hide_banner -loglevel error -y -f lavfi -i sine=frequency=440:sample_rate=44100:duration=1 -ac 2 CODEC_OPTIONS -f hls -hls_time 0.25 -hls_segment_type fmp4 -hls_fmp4_init_filename CODEC-init.mp4 -hls_segment_filename CODEC-%d.m4s CODEC.m3u8
```

| Codec | CODEC_OPTIONS |
|---|---|
| FLAC | `-c:a flac -sample_fmt s16 -strict experimental` |
| MP3 | `-c:a libmp3lame -b:a 192k` |
| AAC-LC | `-c:a aac -b:a 128k` |

The packed fixtures were generated by concatenating the initialization and all
five fragments into one MP4 and demuxing with `ffmpeg -c:a copy`. MP3 additionally
used `-write_xing 0 -id3v2_version 0`, and AAC used `-f adts`. `packed.flac` includes
FFmpeg's ordinary Vorbis comment and padding metadata, which the assembler strips.

`HlsAudioAssemblerTest` runs offline and checks each assembled file against a
known byte hash, metadata, and malformed/encrypted/discontinuous input cases.
`verify-fixtures.py` independently compiles the pure Java assembler and uses
FFmpeg/FFprobe to decode both assembled outputs and the FFmpeg-demuxed reference
streams. It requires `java`, `javac`, `ffmpeg` and `ffprobe` on PATH. Run from any
directory with `python path/to/verify-fixtures.py`.

Verified decoded PCM is signed 16-bit little-endian stereo. All three outputs have
nonzero samples and are byte-for-byte equal to their reference decodes:

| Codec | PCM sample frames | Duration | PCM SHA-256 |
|---|---:|---:|---|
| FLAC | 44,100 | 1.000000 s | `dd0f318ea31da92d3c138a52176a5c5b5239d9dfde28701e7ef950700817c718` |
| MP3 | 46,080 | 1.044875 s | `1f7bb01c0c064f0d23fb005bde59bff64a2539379b52b191473297d57868262b` |
| AAC-LC | 46,080 | 1.044926 s | `cd0cca5607da23bd8464dd56111b4878dacb628cfb4bc6c6433202b36bfab844` |

MP3/AAC elementary streams include the encoder's leading/trailing padding;
container-only edit lists are not carried into elementary stream files. This is
the same behavior as FFmpeg's ordinary stream-copy demux, and does not lose an
audio access unit. FLAC remains exactly one second and its reconstructed
STREAMINFO contains the true 44,100 total samples, with an unknown (zero) PCM MD5.

Android 4.0.4's [AOSP FLAC sniffer](https://android.googlesource.com/platform/frameworks/base/+/android-4.0.4_r2.1/media/libstagefright/FLACExtractor.cpp)
requires the exact prefix `fLaC 00 00 00 22`. It incorrectly rejects the legal
`fLaC 80 00 00 22` prefix used when STREAMINFO is the final metadata block. The
assembler consequently writes a non-final STREAMINFO and a final empty PADDING
block (`81 00 00 00`). This changes no audio frames or decoded PCM; its format
assertions are covered by the real-FLAC fixture regression test.

`getBitrateKbps()` reports the rounded average bitrate of validated MP3 frame
bytes, independent of the bitrate requested from the NAS or stored in MP4's
`btrt`/ESDS fields. It is available after the first complete appended segment and
ignores per-segment ID3 metadata. For FLAC it returns zero; FLAC quality is instead
described by its real sample rate, channel count and bit depth.

While a FLAC file is being assembled, its STREAMINFO total sample count is zero
(the FLAC-standard representation of an unknown total). Complete validated frames
are already decodable, but this alone does not make a growing local file a safe
streaming source: old AOSP derives duration from STREAMINFO and returns duration
zero, and a player that reads past the current file length may permanently enter
end-of-stream. A streaming transport must delay EOF until download completion,
manage its byte range/seek contract, and retain independent track duration metadata.
The assembler fixes the exact sample count on finish; players that already parsed
the header need not re-read that correction. Native Android progressive FLAC
playback behavior under slow or interrupted delivery requires separate device
validation.

Implementation references: [FFmpeg's dfLa writer](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/movenc.c),
[FFmpeg's MOV/fMP4 demuxer](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mov.c),
and [RFC 9639 FLAC metadata/frame definitions](https://www.rfc-editor.org/rfc/rfc9639.html).
The implementation is an independent bounded Java parser, without FFmpeg source
or binary inclusion.
